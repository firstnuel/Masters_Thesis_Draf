## Chapter 1: Introduction

### 1.1 Background
**The Data Deluge**
Log files provide detailed, chronological records of system events, including warnings, errors, configuration changes, and user actions. As modern systems grow in scale and complexity, logs have become essential for performance monitoring, security auditing, transaction tracing, and fault diagnosis. Modern systems generate logs in real time and at massive scale, often exceeding 50 GB or 120–200 million lines per hour in large services.

**The Security Analyst's Burden**
Manual inspection and traditional processing are infeasible due to the scale. Logs are typically unstructured or semi-structured text files generated by logging statements in source code. Because developers are allowed to write free-text messages, the format and semantics of logs vary significantly across systems.

**The Rise of AI**
Log analysis, and consequently anomaly detection, has shifted toward automated, data-driven methods. Early efforts relied on human expertise, but research has moved to rule-based systems, statistical approaches, and machine learning/deep learning to handle the volume and complexity.

### 1.2 Problem Statement
**The "Black Box" Problem**
Deep learning models, while achieving high accuracy in security domains, often function as black boxes, obscuring the features and factors that lead to their predictions.

**The Trust Deficit**
This opacity leads to uncertainty and distrust, especially when an incorrect prediction carries severe consequences. Security analysts cannot trust an alert if they don't know *why* it was flagged.

**False Positives**
Relying solely on keywords or structural features often prevents a large portion of log anomalies from being detected and can lead to unnecessary alarms (alarm fatigue) if the system constantly evolves.

**Lack of Context**
Standard anomaly detectors often fail to capture the semantic nuance between similar messages or complex sequential patterns, leading to false alarms.

## Chapter 2: Literature Review

### 2.1 Log-Based Anomaly Detection

**Traditional Approaches**
Early log anomaly detection efforts relied heavily on human expertise. As the volume of logs grew, methodologies broadly categorized into rule-based systems and statistical approaches emerged.
*   **Parsing**: Log parsing is a critical precursor step where raw, unstructured log messages are transformed into structured data (templates). Parsers like **Drain** incrementally cluster incoming log messages by identifying their constant structure, while **Spell** uses Longest Common Subsequence (LCS) to dynamically identify patterns.
*   **Rule-based**: Relied on explicitly defined rules or keywords (e.g., "error"). However, this approach can lead to alarm fatigue and is hard to maintain.
*   **Statistical Methods**: Leverage mathematical principles to identify normal patterns.
    *   **PCA**: Projects high-dimensional counting matrices into lower-dimensional space to identify anomalies.
    *   **Invariant Mining**: Captures co-occurrence patterns (invariants) between different log keys.
*   **Machine Learning**: Methods like SVM (One-Class SVM), Random Forests (RF), and Isolation Forest (iForest) operate on structured, vectorized representations of logs.

**Deep Learning Era**
Deep learning approaches use neural networks to automatically learn representations from log sequences.
*   **Sequential Models**:
    *   **DeepLog**: Uses LSTM networks to learn normal execution patterns through a forecasting-based approach.
*   **Transformer Models**:
    *   **LogBERT**: Applies BERT to log anomaly detection, using self-attention to capture dependencies across sequences. It uses Masked Log Key Prediction (MLKP) to learn normal patterns.
    *   **LogGPT**: Leverages GPT-2 architecture with causal attention, predicting the next log key based on preceding context.
*   **Limitation**: While DL models outperform traditional methods in F1 scores, they often function as black boxes and may lack semantic understanding if relying solely on templates.

### 2.2 Large Language Models (LLMs) in Cybersecurity

**Capability Shift**
Although system logs differ from traditional natural language, many NLP principles (tokenization, contextual modeling) apply. Logs can be viewed as linguistic artifacts with their own grammar.
*   modern *semantic and language-based* approaches move beyond simple template matching. By leveraging techniques like semantic embedding and Transformer-based modeling, these approaches capture the intrinsic meaning of log events.

**Applications (Pre-trained Language Models)**
*   **BERT-based**: Frameworks like LogFiT use BERT (Masked Language Modeling) to learn deep representations.
*   **GPT-based**: Models like LogGPT use causal attention, aligning with the temporal nature of logs (forecasting).

**Semantic Representation**
Semantic representation converts textual logs into numerical vectors that capture intrinsic meaning. Good embeddings differentiate between distinct events while being tolerant of synonymous variations. Contextualized embeddings (BERT, GPT) allow tokens to be influenced by sequence history, improving robustness against log instability.

### 2.3 Explainable AI (XAI) for Time-Series & Security

**Explainable AI (XAI) Overview**
XAI encompasses methods to help interpret how ML models make decisions. This is paramount in high-stakes security applications where "black box" opacity leads to distrust.

**Post-Hoc Methods**
*   **SHAP**: A game-theoretic approach (Shapley values) that assigns an importance value to each feature (log event). It is model-agnostic but can be computationally expensive.
*   **LIME**: Learns a simple, interpretable surrogate model locally around a specific prediction. Efficient but can be unstable.

**Attention Mechanisms**
Transformer models rely on attention mechanisms that selectively focus on parts of the input.
*   **Attention weights**: Can be leveraged as explanations (magnitude indicates significance).
*   **Visualization**: Tools like BERTViz map attention scores.
*   **Debate**: There is an ongoing debate ("Attention is not Explanation") regarding the faithfulness of attention as a sole explanation.

**Application to Security**
XAI techniques are applied to validate alerts. LIME and SHAP assign relevance scores to log events. Contrastive approaches (DeepAID) and hybrid systems use attention weights to visualize critical tokens.

There is a need for solutions that balance this, potentially through intrinsic explainability or efficient post-hoc methods.
